02 / Método ITVO

De alerta a evidencia

Una secuencia breve para que el análisis sea repetible y defendible.

01

Identifica

Delimita el incidente antes de tocar la evidencia. Registra origen, fecha, equipo, usuario, hash y síntomas observados.

Resultado: una ficha inicial sin alterar la muestra.
02

Contrasta

Compara dominios, IP, hashes y comportamientos con MITRE ATT&CK, VirusTotal y fuentes institucionales. Separa hechos, indicios y suposiciones.

Resultado: hipótesis priorizadas y respaldadas.
03

Contiene

Aísla el activo sin apagarlo innecesariamente, conserva registros, bloquea indicadores y revoca accesos comprometidos. Después restaura desde respaldos probados y comunica el alcance.

Resultado: impacto limitado y recuperación verificable.
03 / Aplicaciones web

Protege la aplicación en el borde

Un firewall de aplicaciones web filtra solicitudes antes de que lleguen al servidor, pero no reemplaza parches, autenticación ni una revisión segura del código.

CDN · WAF · Edge

Akamai App & API Protector

Combina red de distribución, protección contra bots y reglas para aplicaciones y APIs. Es útil cuando se necesita absorber tráfico en el borde y aplicar controles antes del origen.

EjemploBloquear una ráfaga de solicitudes al endpoint de inicio de sesión y permitir el tráfico legítimo con límites por identidad, IP o comportamiento.
WAF · DDoS · Zero Trust

Cloudflare WAF

Permite aplicar reglas administradas y personalizadas, limitar tasas, filtrar bots y proteger servicios publicados detrás de su red global.

EjemploCrear una regla que desafíe solicitudes anómalas a /api/login y registrar el evento sin bloquear de inmediato todo el país.
WAF · Open source

ModSecurity + OWASP CRS

Un WAF instalable junto al servidor web que usa el Core Rule Set de OWASP para detectar patrones como inyección SQL, XSS y traversal.

EjemploComenzar en modo detección, revisar falsos positivos y pasar a bloqueo sólo después de ajustar las reglas para la aplicación.

04 / Protección diaria

Recomendaciones de seguridad web

Pequeñas decisiones técnicas y hábitos de navegación reducen muchas de las rutas más comunes de ataque.

Cuentas

Contraseñas y MFA

Usa una contraseña única y larga para cada servicio, un administrador de contraseñas y autenticación multifactor. Nunca compartas códigos temporales ni los guardes en capturas.

  • Activa MFA resistente al phishing cuando esté disponible.
  • Revisa sesiones abiertas y revoca dispositivos desconocidos.
  • Guarda códigos de recuperación fuera del correo principal.
Desarrollo

Prevén la inyección SQL

La entrada del usuario nunca debe convertirse directamente en una consulta. Usa consultas preparadas, validación del lado del servidor y cuentas de base de datos con privilegios mínimos.

  • Usa consultas parametrizadas u ORM correctamente configurado.
  • No muestres errores SQL ni credenciales en respuestas.
  • Prueba con SAST, DAST y datos de laboratorio autorizados.
Navegación

Reconoce páginas clonadas

El phishing imita bancos, tiendas o servicios conocidos para robar credenciales. No basta con que el diseño se vea igual: verifica dominio, HTTPS, contexto y el origen del enlace.

  • Escribe manualmente la dirección de servicios sensibles.
  • Desconfía de urgencia, premios o amenazas de bloqueo.
  • Reporta la página y cambia la contraseña si la introdujiste.
Aplicaciones

Protege toda la superficie

La seguridad web combina código, infraestructura, identidades, dependencias y monitoreo. Un WAF ayuda, pero no corrige una vulnerabilidad lógica ni una contraseña expuesta.

  • Actualiza frameworks, plugins y dependencias.
  • Configura CSP, HSTS, cookies Secure y HttpOnly.
  • Registra alertas sin almacenar tokens ni datos sensibles.

05 / Memoria operativa

Casos reales para pensar mejor

Los detalles importan. Cambia de caso y observa qué se puede afirmar, qué falta comprobar y qué decisión deja.

Incidente reportadoMéxico · 2024

Coppel: continuidad antes que especulación

Durante 2024 se reportaron interrupciones en servicios y operaciones de Coppel asociadas públicamente con un incidente de ciberseguridad. La lección no es afirmar que una base de datos fue eliminada sin evidencia: es distinguir indisponibilidad, cifrado, pérdida y recuperación.

Pregunta de laboratorio

¿Qué servicio dejó de operar? ¿Qué respaldo existía? ¿Qué indicador comprobaría cada hipótesis?

Consultar fuente institucional
Los casos de Coppel y Telcel se presentan con cautela: los detalles públicos pueden ser incompletos. No se afirma eliminación de bases de datos ni atribución técnica sin una fuente verificable.
